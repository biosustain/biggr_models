# BiGGr 流量构成分析

**分析日期:** 2026-09-04
**数据来源:** nginx access log(单日 781,539 请求)

## 结论摘要

1. **Google Analytics 的 18M 活跃用户不可信** —— 爬虫不执行 JavaScript,不会
   出现在 GA 中。该数字应作为 GA 配置问题排查,不能作为爬虫流量的证据。

2. **爬虫约占 30%,但当前未造成服务器过载。** 请求速率 600–780 req/min,
   CPU/内存/磁盘 I/O 均处于健康水平。

3. **UptimeRobot 告警为误报**(见 2026-08-30 分析):告警期间站点全程正常
   服务,所有探测返回 200,499 状态码表示探测方主动断开。

## 重点发现:伪装爬虫

### 阿里云网段 47.82.0.0/16 + 47.79.0.0/16

| 特征 | 数值 |
|---|---|
| 请求总数 | 76,568 |
| 独立 IP 数 | 3,818 |
| 单 IP 平均请求 | ~68(刻意压在限流阈值下) |
| 峰值速率 | 104.5 req/s,持续 569 秒 |
| 静态资源比例 | **0.20%** |
| User-Agent | 轮换的伪装 Chrome(139/140/141/143,各约 3,900 次) |

**判定依据:** 真实用户浏览会加载 CSS/JS/图标,静态资源占比通常 30–70%。
0.20% 说明只抓 HTML。配合近 4,000 个 IP 分散、UA 均匀轮换,属于刻意规避
限流的分布式爬虫。

**注意:** 该组使用伪装 UA 而非空 UA(全站空 UA 仅 56 条,0.0%),因此
基于 UA 的拦截规则对其无效。

### 未识别爬虫规模

排除已知爬虫后,剩余流量静态资源比仍仅 **1.4%**,远低于真实用户应有水平。
说明"未识别"的 70% 中仍混有大量爬虫,实际爬虫占比显著高于 30%。

## 建议(按优先级)

1. **部署计时日志**(nginx `$request_time`),用 Grafana 观察一周,量化爬虫
   对 P95 延迟的实际影响。当前无数据支撑"爬虫导致不稳定"的结论。
2. **robots.txt 加 Crawl-delay** —— 对 Meta/Google/Ahrefs 等合规爬虫有效,
   可降低约 26% 的流量,零风险。
3. **按 /16 网段限流** —— 针对分散 IP 策略,单 IP 限流无效。
4. **CloudFlare Bot Detection** —— 基于 TLS 指纹和行为识别,是应对伪装 UA
   的有效手段。需评估 DNS 托管迁移的机构合规要求。

## 待验证

- GA 配置为何产生 18M 数字(建议检查 referrer spam 过滤与数据流设置)
- 剩余 70% 流量中真实用户的实际比例(需 TLS 指纹或行为分析)
